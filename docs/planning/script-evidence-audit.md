# 剩余17项证据接入核查

本轮只核查工具、已交付员工端源码和现有读回实现，没有向被测系统发出申请、审批、锁单或故障注入。17项仍是缺口，没有改成专项执行覆盖或通过。

## 已能确认的边界

- 交付的员工端源码 `src/api/apply.ts` 提供客户搜索、图书校验、提交、列表、进度、详情和重新锁单调用。`src/router/routes.ts` 是PC/H5申请及订单页面，不包含经销商管理页面。这个结论仅适用于已交付源码，不能推断另一个管理系统不存在。
- TestPilot现有申请快照查询读取申请号、本人、用途、客户、备注、收件、审批号、模板号、订单号和状态。进度核对比较聚合状态/时间轴。这些已有实现没有独立证明申请当时的组织直属上级和完整企微审批节点；不等于数据库没有其他可用表。
- 现有管理权限读回可查角色键和菜单授权，订单/福利专项可核对数据和部分接口。它们不能替代实际菜单、直接URL拒绝、编辑页面和导出文件核验。数据库迁移记录存在与界面迁移完成分别判定。
- 商品明细聚合接口、库存为零、已取消订单，分别不能证明上游实时查询、查询失败、72小时调度触发或回滚成功。需要同一业务编号的独立事件/版本证据。

以上接口名来自已交付代码，不能当作上游服务完整契约。后端源码不是统一必需条件：必要的接口、组织基线、事件读回或经确认的页面证据同样可用。

## 工具稳定性说明

review.2保留了综合负载下取消检查出现一次时序失败、定向复测通过的事实。本轮尝试以悬挂导航构造更强的取消夹具，测试没有完成验证；该实验已撤回，自有测试进程和其临时档案浏览器已停止。没有足够证据归因于被测业务，未修改产品取消逻辑或降低原测试断言。
