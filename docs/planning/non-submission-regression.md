# 不重复申请的全量回归

## 本轮边界

- 全部用例均进入检查清单；具备只读脚本和数据的实际执行，其他条目逐条记录原因。
- 不发送申请、审批、取消、锁单、下单或通知，不通过 SQL 改状态。
- 本机旧提交授权停用；历史提交结果保留原批次，不能改成新批次通过。
- 原始标题、预期、人工步骤和前置不因脚本修复而改写。
- 脚本错误修复后保留首次失败及后续重测；产品错误保留证据并继续。

## 新增用例的只读专项脚本

实现：`src/adapters/regression/scenarios/records/employee-application-readonly.ts`。

来源必须属于部门用书 V1.1.0，按完整预期精确匹配，当前提供 16 项检查：

- PC/H5 表单的申请人字段、下拉入口、申请类型切换及残留占位；移动检查同时设置视口与移动 User-Agent。
- PC 历史卡片不展示申请类型；历史代人申请须有真实样本，不能用空列表证明。
- 审批状态筛选的完整 DOM 顺序与 OA 文案排除。
- 已取消筛选的新查询、卡片状态、本人身份和数据库归属；超出当前完整分页范围则保留阻塞。
- 本人待审批详情撤销入口及确认弹窗的文案、按钮，实际点“暂不取消”后检查状态不变。
- 本人已取消详情不再显示库存不足提示或再次锁单入口。

入口 DSL 仅供打开已登录表单，最终结果由同条专项断言和本轮截图决定。缺少状态样本、后台角色或接口证据时明确阻塞，不用可见文字子检查冒充完整通过。

## 运行器修正

模块执行的两分钟限制改为“连续两分钟没有单条结果”，每条结果保存后重置计时；持续有进展的较大模块可以执行完成。阻塞现场截图复用当前正确入口，避免每条都先打开空白页。

## 结果存放

真实批次、每条结果与截图保存在本机数据区，可在“执行测试”和“运行报告”查看；本次完整对照及需要人工提交的清单另存于仓库外 `work/`。Git 仅保存实现及通用说明。
