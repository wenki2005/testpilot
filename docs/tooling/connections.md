# 测试连接设置

部门申样工作区的**设置**集中显示当前项目的环境、系统地址、测试账号、数据库及执行服务。设置和数据库查看都留在当前工作区，不会跳到另一个未启动的实例。

## 账号

默认账号及新增账号使用独立浏览器档案。选择账号，点击“连接账号”，在打开的系统窗口完成企微登录；提示待登录时点击“我已登录”。连接检查不会替你提交申请或下单。账号显示“已连接”只代表窗口和当前身份可读，具体权限仍以用例实际结果为准。服务重启后未重新核验会显示“未检查”，不把旧状态当新登录成功。

环境或系统地址变更会隔离原登录档案；历史批次仍保留原地址和环境。需要切回原环境时请先核对当前账号。

## 数据库

输入自己的用户名、密码和TLS方式，点击“连接并检查”。连接后实际读取表清单验证可达性；已有连接可以再次检查。默认校验证书，加密兼容模式由用户明确选择。页面提交后清空密码输入，不把密码回传、写入用例或打入发行包。

数据库连接目前限定现有部门申样测试库；其他环境不会被当作已适配。连接检查只读，不执行用例或修改业务数据。已有数据库私有恢复配置仍遵循原本的本机保存方式。

## 执行服务

已保存的固定脚本和核心链路在本机检查计划、执行断言及汇总证据，不再等待Dify派发确认或汇总回传。相同脚本不重复请求模型整理；失败、阻塞和未执行仍按实际结果保留，数据库证据摘要继续校验。

Dify辅助整理是可选维护能力，使用原有本机Dify环境配置；未配置只影响该可选操作。AI编辑器维护用例通过MCP接入，模型账号属于编辑器，不要求额外内置AI。高级设置保留旧有模型和浏览器配置，默认折叠。

外部审批、库存、通知、订单和物流服务仍是被测业务的真实前置，不会因为取消工具侧Dify确认就自动通过。

## 验证

固定脚本夹具将cloud和author设为抛错，仍能执行原断言并准确保留失败；核心链路也在cloud不可用时执行，保留部分已完成证据和后续阻塞。原有辅助模式的派发、证据指纹及报告保护继续验证。MySQL连接校验使用注入式样例，没有连接或写入真实目标库。
