# 上传完整新版用例

入口：**用例与脚本 → 更新用例 → 上传完整新版**。支持新版XMind（content.json）及当前CSV格式；JSON定义备份仍用“资源 → 导入”。这是整份替换预览，文件里没有的旧用例会列为移除。

## 编号和脚本

- CSV按case_id对应。XMind优先使用topic ID，插入或调整顺序不会重排已有编号。
- 首次接入旧XMind时，用原始预期和路径寻找原用例；重复或无法识别的条目需在预览中选择原编号，或选“新增到此模块”。确认后保存源ID，下次自动识别。
- 未变用例保留已有标题、脚本、前置和版本历史。修改项保留旧脚本并标“脚本待核对”，新增项没有自动编造脚本。
- 核对修改后的操作和断言，保存脚本，再点击“脚本已核对”产生新版本。未核对项不能执行；核对不等于测试通过。
- 移除用例仍被前置或核心链路引用时，预览会阻止应用并指出引用。前置可在资源维护中调整；内置核心链路模板需先维护源码后更新。不会静默删除依赖或修改原有核心链路含义。

## 使用步骤

1. 上传全部用例的最新文件。
2. 看新增、修改、移除、未变及脚本待核对清单。第一次来源绑定单独显示，不算业务内容修改。
3. 有编号歧义时选择原用例，点击“重新预览”。不要仅凭相同顺序认定同一用例。
4. 没有未解决引用后点击“更新”。并发版本变化会拒绝覆盖，重新预览即可。
5. 逐项处理脚本待核对，再从执行测试运行。历史报告仍保留原版本。

当前上传上限8MB；CSV沿用导入器的200条限制，满足当前131条。新增模块及核心链路结构调整通过完整JSON资源预览处理；内置核心链路模板暂不支持随文件静默重写。

## 验证

合成XMind验证首次旧编号绑定、插入和重排；修改项保留脚本并进入待核对；歧义、前置移除、核心引用缺失不能应用。另验证导入后旧版本保留，以及待核对脚本在进入执行流程前被拒绝。
