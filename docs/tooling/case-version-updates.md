# 上传完整新版用例

入口：**用例与脚本 → 更新用例 → 上传完整新版**。支持Markdown（.md/.markdown）、新版XMind（content.json）及当前CSV格式；JSON定义备份仍用“资源 → 导入”。这是整份替换预览，文件里没有的旧用例会列为移除。

## Markdown写法

不要求使用唯一模板，支持常见的以下形式，并识别“预期／预期结果／期望结果”“步骤／操作步骤／测试步骤”等同义字段。

- 表格：包含用例名称、预期结果，编号、模块和步骤可选。例如 `| 编号 | 用例名称 | 操作步骤 | 预期结果 |`，下一行是Markdown分隔行。
- 标题分节：例如 `## xmind-84 | 查找订单`，下面用 `### 操作步骤` 和 `### 预期结果` 分节；也支持无编号标题。
- 字段列表：例如 `- 用例名称：查找订单`、`- 操作步骤：输入订单号`、`- 预期结果：显示匹配订单`；编号和模块可单独列出。
- 缩进树：支持普通正文或markdown/md/text代码块中的XMind式列表。祖先节点保留为导航路径，带P0—P3的末级节点作为预期，例如 `- ✅ P0 显示首页`。优先级保留；✅、❌、⚠️是作者标记，不转换成执行通过/失败。说明和澄清注释不会作为用例。

编号优先匹配，没有编号时按唯一名称及模块寻找原用例。无法确定的条目必须在预览里确认映射；不根据相似文字或排列顺序猜编号。已有XMind来源编号在改用Markdown时保留。

对应关系尚未确认时显示待确认数量，旧用例暂不判移除；完成全部编号/模块确认后才核对最终增改移除和依赖。文件导航目录与现有业务模块不相同时，不能凭相似目录名静默重分模块。

预览的“识别内容”展开显示名称、步骤和预期，应用前核对数量及移除清单。缺少名称/预期、重复编号、错误表格或未闭合代码块会明确提示，不编造内容。仅有自然语言说明或完全无法识别的排版不能直接作为完整新版应用；需明确用例边界及预期后重传。支持UTF-8及带BOM的UTF-16文字。

Markdown提供的操作步骤会更新人工步骤，并触发脚本待核对；固定步骤代码块不会代替现有执行脚本。未提供人工步骤时保留旧值，明确提供空步骤时按空值更新。现有前置依赖保留，不把普通“前置条件”描述自动转成用例编号。

## 编号和脚本

- CSV按case_id对应。XMind优先使用topic ID，插入或调整顺序不会重排已有编号。
- 首次接入旧XMind时，用原始预期和路径寻找原用例；重复或无法识别的条目需在预览中选择原编号，或选“新增到此模块”。确认后保存源ID，下次自动识别。
- 未变用例保留已有标题、脚本、前置和版本历史。修改项保留旧脚本并标“脚本待核对”，新增项没有自动编造脚本。
- 核对修改后的操作和断言，保存脚本，再点击“脚本已核对”产生新版本。未核对项不能执行；核对不等于测试通过。
- 移除用例仍被前置或核心链路引用时，预览会阻止应用并指出引用。前置可在资源维护中调整；内置核心链路模板需先维护源码后更新。不会静默删除依赖或修改原有核心链路含义。

## 使用步骤

1. 上传全部用例的最新文件。
2. 看新增、修改、移除、未变及脚本待核对清单。第一次来源绑定单独显示，不算业务内容修改。
3. 有编号歧义时选择原用例，点击“重新预览”。不要仅凭相同顺序认定同一用例。
4. 没有未解决引用后点击“更新”。并发版本变化会拒绝覆盖，重新预览即可。
5. 逐项处理脚本待核对，再从执行测试运行。历史报告仍保留原版本。

当前上传上限8MB；CSV沿用导入器的200条限制，满足当前131条。新增模块及核心链路结构调整通过完整JSON资源预览处理；内置核心链路模板暂不支持随文件静默重写。

Markdown及XMind最多2000条；长内容继续遵守已有字段长度限制，不会截断原文。当前仅上述三类格式可整份更新，不表示可自动理解任意文件。

## 验证

合成XMind验证首次旧编号绑定、插入和重排；修改项保留脚本并进入待核对；歧义、前置移除、核心引用缺失不能应用。另验证导入后旧版本保留，以及待核对脚本在进入执行流程前被拒绝。
