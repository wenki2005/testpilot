## 修复内容

1. **探索页面失效**：原实现依赖网站 window.open 返回的弹窗目标。改为浏览器上下文直接创建独立受控页面，登录状态通过浏览器内部同源桥复制；不会把存储值读取到 Node 或写入日志。通过模拟弹窗失效、认证接力和连续复用检查。
2. **异步入口变化**：模型选择期间接口数据可能改变控件顺序。点击前重新观察并按入口身份定位，不复用旧索引；地址变更、入口消失或目标不符时继续阻塞。页面快照增加有时限的网络稳定等待。
3. **服务退出**：第三轮复验暴露了关闭页面后网络回调再次 abort 的竞态，抛出 Route is already handled 导致进程退出。HTTP 回调改为安全收敛已完成/已关闭路由，并限制读取超时；页面清理完成后才发布 verified。没有安装吞掉所有异常的全局处理器。
4. **通用选页**：使用页面语义、观察到的路径、当前内容和记录身份选页，替换只靠标题包含以及针对case-75/79的专门路由分支。选择依据保存到地图；任何新路径均来自实际探索，不由模型猜网址。
5. **申请与订单混淆**：真实负例发现模型把申请当订单。加入文档模块和页面类型约束，显式申请编号优先，不允许错误缓存覆盖约束；订单列表下的订单详情用例也必须有实际订单详情页面。
6. **模型结果协议**：最多一次格式/依据修正，发生在任何导航前；模型引用由服务提供的证据ID，服务还原原始文本，拒绝地图外页面和不存在的引用。
7. **工作台状态**：探索完成与本次服务启动后的路径复验分开显示，失败显示具体原因；服务断开时提示自动重连和记录可能过期，恢复后刷新。
8. **编写接入**：页面匹配失败只阻塞当前用例，保留具体原因，不退回首页编写，也不导致同批其它用例整体失败。
