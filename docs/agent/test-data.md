# 测试数据准备（新机器 / 新账号必读）

回归脚本不写死单据号：打开列表后按状态取最新一条。所以**每个账号要自己的数据**。

## 三步

```bash
# 1. 提交 2 张待审批申请（脚本自动执行，会真实建单并通知审批人）
npm run testdata:prepare -- --system <系统ID>

# 2. 让对应审批人在企业微信里处理
#    · 一张「同意」→ 供已通过/待发货/取消类用例使用
#    · 一张「驳回」→ 供驳回类用例使用（可选）

# 3. 跑回归
```

## 数据与用例的对应

| 单据状态 | 从哪来 | 支撑的用例 |
|---|---|---|
| 待审批 | `testdata:prepare` 自动提交 | `2-057` `2-080` `2-085` `2-064` `2-089` |
| 已通过（待发货） | 审批人点「同意」 | `2-067` `2-097` `2-103` `2-081` `2-088` `2-083` |
| 已驳回 | 审批人点「驳回」 | `1-055` `2-073` |
| 已取消 | 撤销待审批单 或 取消待发货订单 | `2-071` `2-079` `2-090` |
| 已发货 / 已签收 | 需真实物流，脚本造不出 | `1-069` `1-085` `2-104` `2-107` `2-108` |
| 锁单失败 | 需库存不足，脚本造不出 | `1-056` `1-064` `1-067` `2-077` `2-086` |

## 注意

- 每次 `testdata:prepare` 都会真实建单，并给审批人发企微提交通知
- 单据只属于当前登录账号，换账号要重新准备
- 待审批数量至少 1 张，已通过至少 1 张；驳回和已取消按需
