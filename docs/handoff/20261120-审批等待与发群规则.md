# 提交申请、企微提醒与审批等待的规则（2026-11-20 确认稿）

适用于三个入口：**自选用例、全部用例、核心链路**。目标是把「什么时候发群、什么时候等审批、按什么顺序跑」从现在的隐式行为改成一套明确规则。

## 1. 术语

- **提交用例**：执行通过后能取到申请编号的用例（结果 detail 里带 `读取：{"applicationNo":...}`），目前是 `xmind-1-050`。
- **依赖审批用例**：只有存在「已通过」的申请才有意义的用例，例如审批人文案、样书明细、字段回显、全部状态入口。
- **本轮依赖集合**：本次选中且可执行的用例里，属于「依赖审批」的那些。

## 2. 规则

| 编号 | 规则 |
|---|---|
| R1 | **发群**：本轮有提交用例、提交成功、且**本轮依赖集合非空** → 发一条企微提醒（申请编号 + 账号 + 等待窗口）。否则**一条都不发**。 |
| R2 | **巡逻**：仅当「有提交用例 + 依赖集合非空 + 提交成功」才启动；每 30 秒**只读**查一次审批进度，最多 10 次（5 分钟）。 |
| R3 | **顺序**：先跑与审批无关的用例 → 再跑提交用例 → 巡逻 → 最后跑依赖用例。 |
| R4 | **跨模块**：全部用例时在批次层重排模块顺序（无依赖模块 → 提交模块 → 等审批 → 依赖模块）；同一批次只提交一次。 |
| R5 | **只读**：巡逻不重跑任何用例，也不给测试窗口装拦截写请求的路由（用户可能同时在该窗口撤回申请）。 |
| R6 | **结局**：通过 → 继续跑依赖用例；取消 → 依赖用例失败「申请已取消（申请 xxx），后续步骤未执行。」；驳回 → 「申请已驳回（申请 xxx），后续步骤未执行。」；超时 → 「审批等待超时（5 分钟）：申请 xxx 未在等待窗口内通过审批。」；状态无法确认 → 「未能确认审批状态：…」按失败处理。 |
| R7 | 未启动巡逻时不发群、也不等待；申请编号写进报告，便于人工跟进。 |
| R8 | 发群结果（已发送 / 未发送及原因）写进提交用例的结果说明。 |

## 3. 「依赖审批」的判定口径（R1/R2 的前提）

1. **自动**：用例的预期或实际结果命中「已通过 / 审批通过 / 审核通过 / 审批结果 / 审批后 / 驳回理由」等，或沿用现有 `looksLikeApproval()` 规则。
2. **手动**：用例上加一个显式开关 `approvalDependent?: boolean`（用例编辑页可勾），**优先于自动判断**。

## 4. 不变的部分

- 核心链路 6 步定义顺序不变，只是发群/巡逻条件按本规则统一。
- 用例脚本、断言标准、审批本身（人工在业务系统里点）都不变。

## 5. 要替换掉的旧行为

- 模块批次现在**无条件**调用 `awaitApproval()`，且每条轮询是**重跑该用例**（有重复提交风险）。改为本方案的只读巡逻，且只在 R2 条件成立时启动。
- 模块批次现在只要提交用例通过就发群（不看有没有依赖用例）。改为 R1。
- `batch-notifier.ts` 里那段算了但没用的 `approvalNotice` 死代码一并清掉。

## 6. 影响面

- `src/adapters/regression/execution/module-execution-service.ts`：拆批执行、只读巡逻、发群条件、移除旧 `awaitApproval`。
- `src/adapters/regression/browser/module-browser.ts`：按批执行并逐条回传（`onResult` 已有）。
- `src/adapters/regression/catalog/module-regression-service.ts`：批次层模块排序（全部用例）。
- `src/domain/documents/**`：用例结构加 `approvalDependent`，加判定函数。
- 前端：用例编辑页加「需要审批通过」勾选；批次/结果里显示「已发群 / 未发群原因」「等待审批中」。

## 7. 验收标准

1. 只勾提交 → 不发群、不等待、结果里有申请编号。
2. 勾提交 + 审批人文案 → 发群一条、只读巡逻；中途撤回 → 后续用例失败「申请已取消（申请 xxx），后续步骤未执行。」
3. 全部用例 → 非依赖模块先跑，提交模块后跑，等审批，再跑依赖模块。
4. 巡逻期间点「停止运行」→ 能中断，批次状态为已取消，已完成的用例保留。
5. 5 分钟无人审批 → 依赖用例失败「审批等待超时（5 分钟）」。
