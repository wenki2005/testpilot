## 二、运行器新增能力

| 能力 | 说明 |
|---|---|
| `{{变量}}` 替换 | `readText` 的 `as` 结果、批次注入的 `applicationNo`、`bookCode`、`accountName` |
| `openLatestRecord.contains` | 按列表卡片文案挑记录，找不到明确失败 |
| `readListRows` | 把列表卡片读成结构化行（时间/编号/状态/申请人）存进变量 |
| `assertRowsSorted` | 按申请时间判升/降序 |
| `assertRowsOwned` | 按账号判列表归属 |
| 空记录诊断 | 打开详情只剩占位图时，报"记录没有可显示内容"而不是"未见文案" |

## 三、卡住的两类（需要数据/UI 支持）

| 用例 | 卡点 | 需要什么 |
|---|---|---|
| `1-064`、`1-067`、`2-086` | 环境里没有"锁单失败"且详情可见的记录；动态定位能找到卡片，但点进去页面为空或不含预期文案 | 一条真实的锁单失败申请（或造一条：用库存为 0 的书提交） |
