# 回归脚本与目录规范

更新：2026-11-04。适用于 TestPilot 的 Dify 模块回归；被测系统代码仍在仓库外，不复制、不修改。

## 0. 当前下载包与存放规范

### 文件名和模块目录

当前“运行结果 → 下载固定脚本”按当前勾选模块及日常/全部/自选范围导出。全选部门申样五个模块并选择全部用例时，必须含13、76、32、7、3条，共131条；未执行、阻塞及范围外定义也保留。

当前范围包命名为：`Dify_<系统名>_<范围>_<模块数>模块<用例数>条_导出<北京时间>.zip`。逐条结果来源记在模块 manifest 中；导出时间不代表执行时间，不创建测试批次。

从页面“历史批次结果 → 下载本批脚本”导出的文件统一命名：

`Dify_<系统名>_固定脚本_<批次北京时间YYYYMMDD-HHmmss>_<批次短ID>.zip`

例如：`Dify_部门申样系统_固定脚本_20261103-230243_8646ff0d.zip`。

```text
Dify_固定脚本/
  README.md                                   # 总说明、运行边界
  Dify_模块索引.md                             # 从原模块名找到目录
  manifest.json                               # owner=dify，系统、批次、模块清单
  modules/
    Dify_申请记录与审批详情_v1_50defb76/
      README.md                               # 此模块的运行方法
      Dify_申请记录与审批详情_固定脚本.mjs       # 一看即可识别模块和归属
      package.json                            # npm test 指向上述脚本
      cases.json                              # 本批用例和步骤，固定协议文件名
      cases.md                                # 原始用例与预期
      manifest.json                           # 模块、版本、任务ID、原结果
      DIFY-CHECKS.md                           # 有额外样式核验时生成
      DIFY-READBACK.md                         # 有本机补充核验时生成
```

- 每模块独立目录。目录名用业务模块名，UUID 只保留8位作为防重后缀，完整ID写入 manifest。
- 文件夹和脚本以 `Dify_` 开头；`owner: dify` 作为机器可读归属，避免和网页回归脚本混淆。
- 模块版本写 `v1`、`v2`；批次时间固定使用创建时间，不以下载时间冒充新执行。
- 保留中文及字母数字；空白、路径分隔符、控制符和其他不适合跨平台文件名的字符转为下划线。系统名最多24字符、模块名最多32字符，避免 Windows 路径过长；原名称保存在索引和 manifest。
- 同名模块使用稳定短ID区分；同一包仍重名时追加序号，不能静默覆盖文件。
- `cases.json`、`package.json` 等是执行器协议名，整模块一起保存；不要为每个文件重复模块前缀后破坏读取关系。
- 主“运行结果”的下载按钮对应当前范围；“历史批次结果”的下载按钮只对应该历史批次。当前范围包收录所有选定用例，历史包的未启动模块在总 manifest 中写 `not_executed`。缺完整步骤的用例保留原预期，独立执行继续报告 blocked。

### 各类内容存放位置

| 内容 | 位置 | 规则 |
| --- | --- | --- |
| 可运行下载包 | 浏览器所选下载目录中的 `Dify_<系统>_固定脚本_<时间>_<批次>.zip` | 解压后按模块查找；不同批次分别保存 |
| 本机最新固定步骤镜像 | `runtime-data/dify/script-index/<系统>/<模块>/<用例ID>.json` | 从模块版本和有效缓存生成；README标明Dify；不手改 |
| 网页回归步骤镜像 | `runtime-data/web-regression/script-index/` | 使用自己的项目准源，和Dify独立 |
| 原始用例包 | `regression/packs/<模块>/` | 原始编号、预期及版本保留 |
| 可提交的既有生成镜像 | `regression/scripts/` | 由导出工具维护，历史结构继续有效 |
| 运行记录与截图 | `runtime-data/<归属>/document-tests/`、`dify-web-modules/`、`system-module-regression/` | 不放进脚本源目录，不进Git |
| 本机凭据与配置 | `runtime-data/<归属>/private/` | 不打包进下载脚本，不进Git |
| 启动/打包/导出工具 | `scripts/`；公共函数 `scripts/lib/` | 工具用途命名，业务固定脚本不混在这里 |
| 审计说明与交付 | `docs/collaboration/`；本机原始审计 `audit/` | 文档进Git，真实记录和私有证据留本机 |

下载包、最新步骤镜像、原始用例和执行证据是四种内容，各自使用上述目录；历史运行引用保持原路径。以下章节的 `regression/scripts/` 结构专指生成镜像，不是ZIP下载结构。

## 1. 三层，别混

| 层 | 放在哪 | 是否进 Git | 谁是准 |
| --- | --- | --- | --- |
| 用例源（原始预期、编号、优先级） | `regression/packs/<模块>/cases.csv` 或 Markdown；导入后存 TestPilot 模块版本 | 是 | 原始 XMind / 业务确认后的版本 |
| 固定脚本（BrowserStep 步骤） | 准：TestPilot 模块版本的 `steps` + 运行期只读场景缓存 `cachedSteps`；镜像：`regression/scripts/<系统>/<模块>/<用例>.json` | 镜像进 Git | 模块版本；镜像是生成物 |
| 执行证据（截图、报告、批次） | `artifacts/`、页面下载 | 否（Git 忽略） | 本轮实际执行，不能用历史截图代替 |

**不要手改 `regression/scripts/`。** 要改用例或步骤，先改 TestPilot 里的模块版本，再重新导出镜像。

## 2. 目录约定

```text
regression/
  packs/                          # 原始用例包（CSV/Markdown，按模块）
  scripts/                        # 生成物：每个用例一份固定脚本镜像
    _index.json                   # 总索引：系统/模块/用例/有步骤/无步骤
    _GENERATED.md                 # 生成说明
    <系统名>/                      # 系统名清洗后的目录
      _index.json
      <模块名>/
        _module.json              # 模块版本、用例索引、缺口
        <用例id>.json              # 该用例的 BrowserStep 固定步骤
  department-apply/               # 旧规划目录，保留，不参与生成
  applications-logistics/         # 旧规划目录，保留
  shared/                         # 公共说明
```

命名规则：

- 系统/模块目录：保留中文，去掉 `\ / : * ? " < > |`，空白转 `-`，最长 60 字符；重名时追加 ID 前 8 位。
- 用例文件：`<case_id>.json`，如 `xmind-17.json`、`local-27.json`；重名时追加短哈希。
- 不要用“最终版/新版/临时”这类名字；版本由 TestPilot 模块版本号表达。

## 3. 命令

TestPilot 运行在默认 `http://127.0.0.1:4319` 时：

```powershell
npm run scripts:export   # 从运行中的 TestPilot 导出固定步骤镜像
npm run scripts:check    # 校验镜像与当前模块版本一致，并检查过期/多余文件
```

其他地址/目录：

```powershell
node scripts/export-regression-scripts.mjs --base-url http://127.0.0.1:4319 --data-dir artifacts/demo --out regression/scripts
node scripts/check-regression-scripts.mjs  --base-url http://127.0.0.1:4319 --data-dir artifacts/demo --out regression/scripts
```

导出会读取每个系统、每个模块的最新版本；把所有用例都写成文件，**没有固定步骤的用例也生成**，状态为 `no-steps`，这样缺口不会被藏起来。导出会清理镜像目录中已不存在的旧 JSON，不会删除其他说明文件。

场景类用例（图书、列表、设备、必填禁用等）的步骤可能在运行时由只读场景生成，存放在模块存储的 `cachedSteps`；导出会优先使用与当前用例指纹一致的缓存步骤，并把来源标成 `cache`。缓存过期或没有缓存时，标记 `derived-at-run`（仅运行期生成）或 `no-steps`，不伪造脚本。

镜像目录默认对应 `artifacts/demo` 数据目录；如果服务使用了其他 `TESTPILOT_DATA_DIR`，导出和校验都要加 `--data-dir <同一目录>`，否则会读不到 `cachedSteps`。

## 4. 新增/修改一条用例的流程

1. 在 `regression/packs/` 或用例管理界面改原始预期/步骤；保留原编号与原文。
2. 导入为模块**新版本**（旧版本保留），不要覆盖历史。
3. 启动 TestPilot（4319），执行 `npm run scripts:export`。
4. 执行 `npm run scripts:check`，确认没有过期/多余脚本。
5. 审查 `regression/scripts/` 的 diff：步骤、预期、版本指纹是否对应。
6. 按用户授权提交/开 PR；未授权只留在本地。

## 4.1 第一版固定清单

第一版不靠记忆选用例，而是 `regression/plans/first-version-2026-11-01.json`：系统、模块、模块版本、用例编号都固定。

```powershell
npm run plan:run -- --plan regression/plans/first-version-2026-11-01.json --dry-run
npm run plan:run -- --plan regression/plans/first-version-2026-11-01.json
```

计划里的 `versionId` 不是最新版本时会拒绝执行，避免模块升级后偷偷换用例；`excluded` 记录 29（BUG-003）、52（逆向/后续再加）等暂不纳入的条目。单条重测另记在 `runs`，不拼回原批次。

页面改版导致定位失效时，改**对应用例的步骤/新版本**，不要改工作流，也不要动其他用例。

## 5. 脚本分类

| 位置 | 放什么 | 规则 |
| --- | --- | --- |
| `scripts/` | 构建、启动、打包、导入导出、数据工具 | 入口脚本，文件名动词开头 |
| `scripts/verify/` | 一次性验收/审计脚本（新脚本放这里） | 必须能在 README 找到用途和运行命令 |
| `scripts/lib/` | 脚本共用函数 | 不放业务预期 |
| `regression/scripts/` | 生成的固定用例脚本镜像 | 只读生成物，不手改 |
| `regression/plans/` | 固定批次清单（系统/模块/版本/用例编号） | 快照，不改历史；用 `npm run plan:run` 执行 |
| `tests/` | TestPilot 自身测试 | 用 `node --test` / `npm run test:all` |
| `artifacts/` | 本机运行证据 | 不进 Git |

旧的 `scripts/verify-dify-*.mjs` 等审计脚本暂时保留在原位，逐步迁到 `scripts/verify/`；新脚本不再放 `scripts/` 根目录。

## 6. 代码规范

- `src/` 只放 TestPilot 工具代码；按 `adapters/`、`domain/`、`demo/` 分层，不把某个被测系统的业务逻辑写进共享层。
- TypeScript 严格模式；改完跑 `npm run typecheck`、`npm run typecheck:web`；构建跑 `npm run build`。
- 测试放 `tests/`，文件名 `*.test.mjs` 或 `*.integration.test.mjs`；工具测试和业务验收分开统计。
- 不提交 `.env`、密钥、Cookie、浏览器 profile、数据库备份；用例里也不写真实凭据。
- 不改被测系统；不提交/审批/取消业务，不写目标数据库。
- 一个任务一个分支，提交前说明改了哪些文件、跑了什么命令、实际结果和未验证项。
- 其他栏目/其他人的系统保持独立；本规范只约束 TestPilot 仓库和 Dify 回归工作台。
