# 用例和脚本存放规范

更新：2026-11-05。

| 内容 | 位置 |
| --- | --- |
| 当前用例、脚本、前置和核心链路快照 | project-resources/department-sample/ |
| 原始编号和预期来源 | regression/packs/ |
| 当前前置编号维护清单 | regression/plans/ |
| 测试执行实现 | src/adapters/regression/ |
| 运行记录、截图、登录态和私有配置 | runtime-data/、artifacts/，不进 Git |

每条用例和脚本按稳定 ID 定位；文件名不用“最终版”“临时版”。当前网页模块版本及有效步骤缓存仍是执行准源，直接修改快照暂不会同步回网页。

前置用例必须执行通过。原始标题、步骤和预期不能为制造通过而改动；脚本有内容不等于用例已通过。运行证据对应实际批次，不能拿别轮的结果冒充本轮执行。

当前快照导出：npm run resources:export -- --system <UUID> --out <新目录>。比较后替换当前快照，不在源码里累积多份旧导出。steps 缺失的用例保留定义，不编造步骤。

旧 regression/scripts 镜像已移除。npm run scripts:export 与 scripts:check 仍支持显式 --base-url、--data-dir、--out，用于需要步骤镜像时按当前运行实例重新生成。镜像是生成物，不手改，也不作为另一套用例源。

页面下载脚本包沿用既有协议：模块目录中的 cases.json、package.json、manifest.json 等文件名由执行器读取，不因整理而改名。导出时间不代表执行时间，下载不创建新批次。

程序目录与命名见 [项目目录](../project-layout.md)、[命名规范](../naming-conventions.md)。
