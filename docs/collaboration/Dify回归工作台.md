# Dify 回归工作台

当前默认入口已统一为 **Dify 模块测试**，支持模块上传、真实 Dify 三阶段编排、本机网页执行和结果回看。普通使用流程见 [Dify模块测试使用说明](./Dify模块测试使用说明.md)。旧 tab 链接兼容到新主页面；以下保留旧版整理和人工记录说明，对应页面底部“历史与高级功能”，不代表当前自动测试流程。

## 旧版整理与人工记录

入口是 TestPilot 网页的「Dify 回归工作台」。Dify 负责整理原有用例；TestPilot 负责保存来源、草稿版本、审核意见和人工回归记录。当前功能不会自动操作被测系统。

侧边栏统一保留一个「Dify 回归工作台」入口，内部有「整理用例」与「按模块执行与记录」两个页签。前者对应本文的草稿流程；后者的自动接口执行见《固定模块执行》。页签切换保留尚未提交的表单内容，刷新后保持当前页签；旧 `?page=module-regression` 链接会打开统一工作台的执行页签。

## 本机启动

1. 在 `.env` 配置 `TESTPILOT_DIFY_API_KEY`，可选配置 `TESTPILOT_DIFY_WORKFLOW_URL`。真实密钥不可提交 Git。
2. 构建项目 `npm run build`。没有 npm 命令时，用 Node 依次运行项目内 TypeScript 和 Vite 工具。
3. 双击仓库根目录的「启动Dify回归.cmd」。默认地址为 `http://127.0.0.1:4319/?page=dify-regression`。

Dify 工作流模板位于 `integrations/dify/regression-drafts.yml`。导入 Dify 后检查模型供应商是否可用，发布工作流，再将该应用的 API Key 配置到本机 `.env`。普通演示启动和 `demo:start` 也会读取 `.env`；已有进程需要重启才能读取新值。

## 日常操作

1. 导入第一版人工 XMind，或保留来源字段的 JSON。新版 XMind 直接解析 `content.json`；原文件的 SHA256、叶子节点编号和完整路径保留。叶子节点不一定就是独立可执行用例。
2. 按模块筛选并勾选，每次最多 12 条。按钮变灰时，查看按钮前的具体原因。全部来源都能分批整理；待澄清、本期不做、计划功能及白盒补充需人工决定范围。
3. 点击「用 Dify 整理」。任务先落盘，再调用 Dify；失败也留档，不生成已通过的测试结果。
4. 展开草稿核对原文与提议步骤，填写审核人和审核意见后批准或退回。Dify 输出成功不等于人工审核完成。
5. 填写系统版本、数据快照标识和测试人，创建本轮记录。实际测试后逐条记录状态、实际现象和证据位置。通过、失败必须绑定本轮创建时的批准记录。
6. 刷新、重启后可继续查看历史；用「导出全部记录」保存 JSON 副本。

## 保存位置和限制

记录数据库是 `${TESTPILOT_DATA_DIR}/dify-regression/regression.sqlite`；未配置数据目录时默认为仓库的 `artifacts/demo`。它是测试工具自己的本机 SQLite，与被测系统的 MySQL `supply` 无关。原始 XMind、记录、密钥均不放进 Git。

网页目前仅监听本机；两人各自启动时拥有各自记录，Git 不会同步运行数据库。需要共同查看同一份运行记录时，应单独部署带登录和权限的共享服务，不能仅靠 Git 同步 SQLite。

原文预期、路径和编号由程序直接复制；模型只提议标题、准备条件、步骤和待确认项。Dify 和本地服务分别检查编号完整性及状态。工作流日志可能到期，本机记录独立保留。服务中断时，未完成整理任务标为失败，需要重新发起。
