# Dify 模块测试使用说明

## 使用

1. 双击仓库根目录“启动Dify回归.cmd”。默认地址为 http://127.0.0.1:4319/?page=dify-regression 。代码有更新时，先构建并重启旧进程。
2. 上传 CSV 模块用例包，填写被测网址，点击“开始测试”。已有模块可从右上角选择后直接复跑。
3. 出现“等待登录”时，在 TestPilot 打开的项目测试窗口登录，再点击“我已登录”。普通浏览器或 Dify 的登录态不能自动等同于这个项目的会话。
4. 在当前页面看进度和逐条结果。“查看”可打开原始预期、实际观察、截图和 Dify 建议。
5. 用“重测失败项”或勾选用例后重测。历史下拉可以回看旧轮次；“下载报告”保存本轮 Markdown 报告。

用户不需要修改 JSON、编写测试脚本或绑定固定 API 套件。模块包没有步骤时，系统只在原始预期明确且页面证据支持的情况下自动准备步骤；其余条目说明具体缺口。

## 格式与结果

- 当前主入口支持 CSV，最多 4 MB / 200 条，必需列为 case_id、title、steps、expected_result。steps 可以是包内已有的 JSON 动作数组或空数组，普通使用者无需手动修改；需要明确原始预期。
- 第一期只自动执行只读页面动作。提交审批、外部推送、数据库持久化、跨角色权限等完整业务预期可能阻塞，不能用部分页面检查代替。
- “通过/失败”来自真实断言。“Dify 汇总失败”属于流程问题，已保存的真实测试结果不会消失；重试汇总不会重跑浏览器。
- “本轮完成”表示流程结束，不表示所有用例通过。原包数量、本轮选中数量及实际执行数量分别记录。
- “流程记录”内可找到本轮 ID、网页运行 ID、Dify 各阶段 ID。旧人工登记与固定 API 记录放在“历史与高级功能”，不与新自动测试混算。

## 配置

本机 .env 需要 TESTPILOT_DIFY_API_KEY（用例整理）和 TESTPILOT_DIFY_EXECUTION_API_KEY（固定派发与汇总）。密钥不进入页面、报告或 Git。数据保存在 artifacts/demo/dify-web-modules，网页执行和截图保存在 artifacts/demo/document-tests；设置 TESTPILOT_DATA_DIR 时统一切换数据根目录。

独立验证：运行 `node scripts/verify-dify-web-module.mjs`。它生成 examples/dify-web-module-sample.csv，并用真实 Dify 和本机受控网页验证通过、已知失败、无脚本步骤准备以及失败项重测；结果明确标记为受控样例。
