## 后续持续开发和推送

你可以继续在原目录修改脚本。这个集成副本只包含明确时点的代码快照；它不会自动获得之后的修改。

最终切换或推送前应按以下顺序操作：

1. 对比原目录与快照，列出新增、修改和删除的文件；原目录有未完成的文件修改时先保持原状。
2. 把确认好的增量保存为新提交，再通过 Git 合并到集成分支。共享引擎有冲突时按语义处理，不能直接覆盖整文件。
3. 对增量影响的模块重跑检查，确认脚本、原始编号、原始预期及批次数据兼容。
4. 使用独立数据目录预览；安排明确切换时点后再更新运行目录。
5. 推送集成分支到 GitHub，通过 PR 合并。当前阶段只完成本地集成，没有推送远端。
