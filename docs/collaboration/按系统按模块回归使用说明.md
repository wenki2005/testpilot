# 按系统按模块回归

启动：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start-dify.ps1`。默认本地页面 `http://127.0.0.1:4319/?page=dify-regression`。

## 日常操作

1. 选择被测系统。
2. 首次使用点“连接我的账号”，在系统专用测试浏览器中登录；等待登录时回到本页点“我已登录”。没有登录成功或权限不足会阻塞，不算通过。
3. 勾选一个或多个固定模块，点“开始回归”。每轮自动保存所选模块，下一轮可点“恢复上次选择”。
4. 模块按勾选的清单顺序执行；一个模块失败不妨碍其他独立模块。登录失效会等待用户接续，取消后未启动模块保持未执行。
5. 在本页选择一轮运行记录，查看模块、用例及截图，下载整轮报告；可重测失败或未完成模块。前置数据需要确认的用例，在实际结果详情中点“前置数据已准备，重测此项”。

## 首次设置与维护

- “新增系统”保存系统名、测试网址、环境。系统各自使用独立浏览器配置，同系统模块复用登录状态；更换网址或环境后要重新连接账号。
- “管理模块”导入 CSV 用例包，并命名为固定业务模块。用例必须有唯一 case_id、title、expected_result；人工步骤也可导入，Dify 和本地执行器会尝试形成可靠步骤，无法验证的保留阻塞。
- 更新包时选择已有模块，上传更新 CSV。模块身份保留，用例新增、修改、移除计入新版本，旧版本与旧报告仍可查看。原始预期不会被 AI 结果覆盖。
- 暂不支持 ZIP 导入；请选模块包目录里的 cases.csv。
- 归档可逆，不删历史；恢复后再次出现在主表。
- 旧包在“管理模块 → 历史用例包”中显式归入系统；原单包运行在“历史与高级功能 → 历史单包测试记录”中保留。

## Dify 与执行证据

固定模块的本轮原始用例与版本快照进入真实 Dify，执行计划和派发经过校验，本地浏览器实际测试并截图，再由 Dify 汇总。无需用户写脚本或改 JSON，不跳到网页回归页面。

每轮保存系统/环境/网址、所选模块和版本、Dify 阶段运行编号、网页运行、逐条实际结果及截图。批次完成只表示队列结束，是否通过以结果计数为准。失败、阻塞、异常、未执行和范围外分别呈现。

历史重测使用原轮版本；更换环境后不能把新环境执行伪装成原轮重测。服务重启保留中断记录，不自动重放。

## 本机已导入

部门申样系统已保存 5 个模块共 131 条归档用例：登录入口与公共基础 13、申样申请与经销商数据 76、申请记录与审批详情 32、订单与物流 7、PC/H5 横向适配 3。25 条待复核补充项未自动导入日常目录。

131 条是归档数，不能理解为已通过或全部可自动执行。业务系统目前还需要企业微信登录；需要身份、数据、服务端证据或提交/审批写操作的用例会按当前只读边界阻塞，不执行写入，也不降低原始预期。

“本地流程验证系统”是独立受控样例，只用于验证 Dify 和网页执行链路，其结果不代表部门申样系统业务通过。
