# Dify「删除样书行」共享动作：影响、风险与回退说明（2026-11-02）

状态：**仅影响说明，未修改共享执行器。** 等用户判断后再决定是否改动。范围仍限 Dify 回归工作台，未触碰被测系统、未创建/删除任何业务记录。

## 1. 现状：这个动作到底落在哪

`deleteSampleRow` 不是 Dify 局部代码，它落在共享执行器 `src/adapters/document-test-workflow.ts`，共 5 处：

| 位置 | 作用 | 现状 |
| --- | --- | --- |
| 第 37 行 | `BrowserStep` 联合类型新增分支 | 只允许可选 `rowIndex` |
| 第 829–832 行 | `validateCases` 入库校验 | 仅校验 `rowIndex` 为 0–9 的整数；不校验目标表格、不校验“未提交” |
| 第 1289 行 | `isSafeReadOnlyBrowserCase` 安全门 | 直接 `return true`，注释自称“scoped to UI-only sample-detail rows”，但门禁本身没有做任何结构判定 |
| 第 1791–1803 行 | 主执行器 | `page.locator("tbody tr").filter({has: 文本“删除”})`，页面上**任意**含“删除”单元格的 `tbody tr` 都算候选；`rowIndex` 缺省取**最后一行**；点击后只等 300ms |
| 第 240114 字符附近 | 导出脚本里的 `run.mjs` 模板 | 与主执行器**同逻辑的另一份拷贝**（同样的 `tbody tr` + “删除”定位） |

识别侧：`src/adapters/dify-case-readiness.ts` 第 22 行把“每行提供删除按钮”文本或已含该步骤的用例判为可执行，不做结构复核。

现有测试只有 `tests/dify-delete-sample-row.test.mjs` 3 项：动作被接受、`rowIndex` 越界拒绝、普通 `clickExactText("删除")` 仍被拒。**没有任何一项在真实 DOM 上证明“只会点到未提交的样书行”。**

## 2. 其他入口 / 导出 runner 的影响面

`executeDocumentRun` 是共享入口，调用方有 3 处，`deleteSampleRow` 一改全部受影响：

1. `src/demo/server.ts` 第 2349、2373 行——本地工作台的文档/网页回归批次。
2. `src/adapters/dify-web-browser.ts` 第 109 行——Dify 模块批次（35 走的就是这里）。
3. 导出的独立脚本 `run.mjs` 模板——`dify-script-package.ts` 用 `difyPortableRunner()` 只替换“结果断言动作白名单”，**不替换执行分支**，所以导出包会带着同一份逻辑；改主执行器而漏改模板，就会出现“工作台通过、导出包行为不同”。

因此任何收紧都必须**两处同改**（主执行器 + 导出模板），并补一条“两处一致”的检查，否则两条执行路径会漂移。

## 3. 风险（按严重度）

1. **可能点到真实业务删除。** `tbody tr` 是整页范围。页面若同时存在图书明细、地址簿、附件等其他带“删除”的表格，同样命中；`page.on('dialog')` 未注册，Playwright 默认自动 dismiss/确认，遇到二次确认弹窗可能被自动放行。
2. **无法证明行是“未提交”。** 没有任何断言证明目标行是本次新加、尚未落库的样书行；如果该行已被服务端保存，点击就是业务删除，与“不删除业务记录”的授权边界冲突。
3. **`rowIndex` 缺省取最后一行**，语义上等于“随便删一行”，不是“删我刚加的那行”。
4. **没有删除后校验**：未断言行数恰好 −1、未断言其他行不受影响、未断言没有发出非 GET 请求。
5. **安全门名不副实**：第 1289 行无条件放行，等于共享安全策略对该动作失效；其他栏目/他人模块若导入含此步骤的用例，也会被同样放行。
6. **导出包行为差异**：模板同源复制，改一处不改另一处会让独立 runner 与工作台不一致（35 的验收正是靠导出包复核）。
7. **回滚成本低但影响面宽**：一旦误删，没有自动恢复；只能靠被测系统自身流程人工处理。

## 4. 建议的最小改法（供判断，未实施）

只动共享执行器的这一个分支，不新增 BrowserStep 字段以外的模型：

- **受控容器**：新增可选 `container`（默认“样书明细”），要求页面上含该文案的表格**唯一**，否则 `Blocked`，不再全页 `tbody tr`。
- **行级证明**：仅允许操作容器内**最后一行**且该行带“删除”的行；若 `rowIndex` 与“刚新增行”冲突则 `Blocked`，不猜。
- **写入防护**：点击期间拦截所有非 GET/HEAD 请求（沿用 `triggerClientValidation` 的做法）；一旦出现写请求，立即 `Blocked` 并报告“该删除会落库”，由用户判断，而不是放行。
- **对话框防护**：注册 `page.once('dialog')`，出现确认框即 `dismiss` 并 `Blocked`，不自动确认。
- **删除后断言**：行数恰好 −1、目标行消失、其他行文本不变、无写请求。
- **双份一致**：主执行器与导出模板同步改；加一条测试直接比对两段逻辑的关键判定（容器唯一 + 非 GET 拦截 + 对话框拒绝）。
- **测试补充**：真实 Playwright 夹具覆盖“只有样书表”“多表都有删除”“确认框”“触发写请求”“容器缺失/重复”五种情况。

## 5. 回退方案

- 代码回退：撤销上述 5 处 hunk（类型、校验、安全门、主执行器、导出模板）+ 新增测试；`npm run build` 重新生成 `dist`，`npm run scripts:export` 重新生成镜像。
- 行为回退：撤掉动作后，xmind-35 回到“被安全策略拒绝”的阻塞状态（10-31 起的既有状态），已有批次结果不改写、不重算。
- 数据影响：不需要迁移或清理；该动作不写数据库，回退不涉及旧批次、旧截图或模块版本。
- 风险残留：回退后 35 仍不可执行，属已知边界，不得算通过。
