# 用例与脚本模块

用户确认精简预览后实施；入口为 `?page=case-scripts`，属于 Dify 数据区。旧 `?page=regressions` 保留原回归断言页面。其他页面的内容与数据归属保留。

## 已实现

- 全部目录读取当前项目未归档模块；部门申样为五个模块、131 条。核心目录引用既有四条链路的 24 条去重原用例，顺序沿用链路定义。两种目录编辑同一份源，不复制出第二套用例。
- 中栏编辑名称、人工步骤、预期和前置用例；保留 XMind 编号、路径和最初版本预期。未有人工步骤时显示为空，不使用预览示例补写。
- 右栏读取模块步骤及有效缓存，编辑 JSON 固定脚本。支持复制脚本和该版本脚本接口地址；不声称本地生成镜像文件已经导出。
- 保存形成新的模块版本；旧版本、原始用例及已有执行快照保留。恢复旧版本先载入编辑区，再由保存生成新版本。没有草稿箱；修改仅存在当前编辑区，切换和关闭提醒未保存。
- 使用模块版本号进行并发保存检查，拒绝运行期间保存，校验 JSON、编号、原有 BrowserStep 协议、同项目依赖及依赖环。
- 前置状态读取同项目、同账号、同环境的最新对应源结果；编辑后的源不能借用旧源通过结果。新增依赖在系统批次及单包入口派发前由服务端检查，未通过则拒绝执行当前范围。需先执行前置用例，再执行依赖用例。
- 明确修改的固定步骤按新版本执行，不被原有只读计划静默替换；现有页面、只读、断言和业务写入检查仍然生效。未编辑用例继续原逻辑。

## 边界

原有执行测试页面、四条核心链路的专用执行器、报告和其他工具页面没有改写。核心目录提供原用例引用管理，不把核心步骤的独立结果冒充原 XMind 用例的最新结果。没有自动新增测试依赖关系；现有文本前置条件仍保存在原用例中，结构化前置用例由用户明确选择。

修改固定源之后，生成脚本镜像仍按既有 `scripts:export` / `scripts:check` 规范操作；编辑器不直接修改生成目录。
