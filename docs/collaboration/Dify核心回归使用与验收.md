最新状态请先看本文末尾与 `dify-core-regression-progress.md` 最新章节；下文带时间的验收是历史记录，不代表当前固定范围仍有同样的失败和阻塞。

## 日常如何使用

1. 选择系统与测试账号，点击连接账号；需要登录时在测试窗口完成，然后点击“我已登录”。账号窗口独立保存登录态，密钥和密码不用填入用例包。
   已绑定部门申样只读数据库时，连接后可展开“运行准备”，提前看到该账号是否有申请记录。数据未准备不等于登录失败；实际测试仍会重新核验。
2. 首次在“管理模块”导入 CSV 或 Markdown 包。更新仍选择同一个模块，生成新版本，旧版和历史保留。Markdown 模板可在管理入口下载，填写原始步骤和预期即可，无需编写脚本或 JSON。
3. 打开“查看用例”，勾选日常重点用例，保存为最小回归；核心范围另行保存。原始完整包仍保留，最小与核心互不覆盖；更新版本后需要重新确认范围。优先级可筛选，默认等级不等于已人工评审。
4. 新包没有可靠步骤时选“AI 辅助整理”，让内容实际进入 Dify 工作流；生成步骤经过本地覆盖检查，不能执行的场景仍阻塞。日常选择“最小回归 + 固定回归”，复用原包或此前保存的步骤，跳过重复模型整理，仍真实调用 Dify 派发与汇总。
5. 勾模块后开始，结果、原始预期、截图、数据库补充核验和报告都留在本页。可以单条运行、运行所选、只重测失败或未完成项。没有固定步骤时，固定回归会明确阻塞。
6. 汇总失败时使用“重试汇总”，不会重复网页执行。“继续未执行”只把原轮尚未执行的用例放入关联新轮，重新检查登录和环境，不是从浏览器某一条点击中间恢复。
7. 结束后可下载报告与本轮固定脚本包。包内有依赖和运行说明，不含登录态、密码或数据库原始记录；独立脚本使用本地浏览器运行，不会自动接入 Dify 或数据库。没有完整断言的项保留阻塞，导出不能把它们变成通过。
8. 异常通知默认关闭，设置折叠在“系统设置 → 异常通知”。指定测试群机器人地址在本机环境变量配置后，才能开启摘要；截图需另外勾选。每轮最多发送前 3 张失败截图，不发送数据库原始数据。通知状态在“Dify 流程记录”中查看；明确失败可重试通知，接收结果不明时先核对群消息，不自动重发。

下载不会跳离工作台。材料包含密码、密钥等凭据时会明确拒绝导出；不会把原始预期悄悄脱敏后当成完整原文。请将凭据留在本机账号配置和登录窗口，测试包保留业务步骤与预期。
