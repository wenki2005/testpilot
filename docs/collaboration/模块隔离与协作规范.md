# 模块与数据边界

更新：2026-11-05。当前使用方式以根 README 和实际网页为准。

- 页面按 web/src/features/<功能>/ 维护；后端按 domain、application、adapters、interfaces、storage 分层，层内按功能分类。
- 修改共享执行器、数据契约或导出协议时检查所有调用方，保留接口 URL、稳定用例 ID 和存储协议。
- 运行目录、截图、账号、数据库文件与资源定义分开；runtime-data 和 artifacts 不加入 Git，不打包进业务资源。
- 现有工作区仍有 dify 与 web-regression 两套数据路径，启动、导出、迁移必须选择对应工作区，不混读或覆盖另一边的数据。保留路径不代表当前界面需要突出两套方案。
- 不移动正在使用的数据库和浏览器登录目录。01、02、04中的目录联接是导航入口，不是已完成物理迁移的证明。
- 用例原始来源保留，历史程序副本、过期计划、重复转发和一次性修复不在当前源码目录累积。历史版本由 Git 追溯。
- 不覆盖他人未提交改动。公共改动在分支完成，提交前检查差异；推送、合并按用户授权进行。

资源文件同步回网页、首次安装初始化、完整发行包装配及 MCP 维护接口仍待实现，不能把页面说明或定义快照当作功能已完成。
