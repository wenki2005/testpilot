# Dify 模块回归：测试数据库接入

本次接入的是用户提供的部门申样测试环境 MySQL `supply`，不是生产数据库。数据库密码、登录态、个人资料和原始记录编号不进入 Dify、Git 或此文档。

## 使用

在“模块回归”选择“部门申样系统”。系统设置中的“核对部门申样测试库（只读）”开启后，开始回归会自动采集数据库证据，无需编写 SQL、脚本或修改 JSON。数据库连接沿用本机 MySQL 数据查看工具；服务重启后连接池需要重新连接。

本次已为现有部门申样系统开启。其他网址不能绑定此测试库。更换环境后浏览器账号重新隔离；历史重测沿用历史数据库绑定，不随当前设置悄悄改变。

## 实际执行流程

1. 连接该系统的浏览器窗口，使用用户在该窗口完成的登录。
2. 本机以 TLS、SELECT 账号及只读事务执行固定查询：有效申请量、有效明细量、明细关联完整性。
3. 在同一系统窗口重新打开无筛选“我的申请”，监听本页真实 GET 响应及当前登录身份。只在内存中使用当前身份/本页编号进行参数化查询。
4. 比较当前身份对应的申请总数与列表总数；对当前页最多 10 条记录比较编号对应关系、接口提供的审批/锁单状态字段。
5. 有当前账号记录且列表核对成功时，打开该记录的申请明细页面，比较最多 100 条明细的数量和单价，并确认主要页面区块可见。无个人记录则明确阻塞详情，不借用全库其他人的记录。
6. 仅将固定说明、数量和核对结果传给 Dify 用例整理工作流。原始预期和用例编号完整保留，数据库现场数据不充当新的业务预期。
7. 执行计划指纹绑定数据库证据指纹，Dify 派发后由本机执行网页用例。数据库脱敏摘要另经同一 Dify 执行工作流的 report 分支汇总，核对任务、版本、证据指纹和统计。
8. 同一任务保存 Dify 编号、网页运行编号、截图、数据库快照和报告。页面“数据库核验”展开查看；下载报告也包含这些证据。

云端工作流接收摘要并整理/校验汇总；实际 SQL 读取及网页操作在 TestPilot 本机完成。本次没有把数据库账号交给云端，也没有修改云端工作流的管理配置。

## 与未接入的区别

| 项目 | 未接入 | 接入后 |
| --- | --- | --- |
| 数据准备 | 只凭页面现象判断 | 能知道全库有无数据、当前账号有无数据 |
| 页面与数据 | 只看 DOM/接口表现 | 可对当前账号的列表和样书明细做只读对照 |
| 定位阻塞 | 登录、权限、数据原因容易混杂 | 分开显示连接、数据量、关联、个人列表、明细核对结果 |
| 证据 | 页面截图和断言 | 同轮增加数据库时间、检查结果和防篡改指纹 |

补充核验不计入 XMind 用例通过数；数据库断连、空记录、字段不明、明细键重复等都不算通过。数据库补充核验失败时模块整体失败；补充核验阻塞时，即使网页断言全部通过，模块整体也保留阻塞。已有历史结果不回写。

## 覆盖边界

此轮是已有数据的只读核验，不创建申请、发起审批、重新锁单或操作物流。状态数值的一致性不代表审批按钮颜色、权限矩阵、状态流转已通过。明细数量/单价一致不代表地址、申请人、重量、金额计算等全部 XMind 预期通过。只有本机收集到的可靠字段才比较；缺字段明确阻塞，不猜测映射。

网页读取规则同时修复了前端真实使用的 `myList`、`detail/{编号}`、`progress/{编号}` 和物流只读列表地址。这些仅在指定测试 API 主机上允许 GET/HEAD/OPTIONS；提交、审批、重新锁单及其他写入仍不允许。

只读查询使用固定表、字段和参数化条件，设置执行时间上限；不接受模型生成的任意 SQL。所有事务结束均回滚。
