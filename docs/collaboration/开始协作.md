# 开始协作

共享仓库：[wenki2005/testpilot](https://github.com/wenki2005/testpilot)，可见性为公开，主分支为 main。2026-11-01 起统一回到创建者的仓库；新电脑恢复 Dify 配置请先读 [新电脑交接](Dify新电脑交接-2026-11-01.md)。运行数据、密钥和私人迁移包不上传此公开仓库。

共享代码根目录是当前内层 TestPilot 文件夹。被测前端仍留在原目录，数据库仍是独立测试服务。双方以后克隆同一个共享仓库，不互相覆盖整个文件夹。

## 首次准备

安装 Node.js 22.19 或以上版本及随附 npm，安装 Git。首次配置各自真实姓名和邮箱：

```powershell
git config --global user.name '你的姓名'
git config --global user.email '你的邮箱'
```

另一人在自己的电脑执行；推送前需接受创建者的协作者邀请：

```powershell
git clone https://github.com/wenki2005/testpilot.git TestPilot
cd TestPilot
npm ci
npm run build
npm run demo
```

当前机器的 Node 可用，npm 不在 PATH；已安装的 node_modules 可以用于本机验证。新电脑应安装带 npm 的标准 Node.js 发行包，不能只复制 node_modules 当作交付。

模型配置按根目录 README 设置，各自维护本机密钥。回归环境字段参考 .env.regression.example，该文件是记录模板，不会自动接入 MySQL。

## 每个任务

先检查工作区。没有未提交修改时，开始新任务：

```powershell
git status
git switch main
git pull --ff-only
git switch -c test/apply-required-fields
```

当前本机已经连接远端 origin。另一位同学克隆后也会自动获得 origin，无需再次初始化仓库。

按原 XMind 完成一个小任务，运行相关验证，核对新文件和已改文件，再提交：

```powershell
git status
git diff
git add .
git diff --cached
git commit -m '补充申样表单必填校验回归'
git push -u origin test/apply-required-fields
```

在平台申请合并到 main，对方核对用例依据和实际结果后再合并。后续新任务从最新 main 新建分支，任务未完成则继续原分支。

## 查看远端和上传

本机 origin 指向同一个私有仓库，不要重复执行 git init 或 git remote add。可用下面命令核对远端；日常仍通过任务分支和合并请求协作。

```powershell
git remote -v
git branch --show-current
```

commit 只保存在本机，push 后对方才能取得。仓库所有者在 GitHub 的 Settings → Collaborators 邀请另一位同学，接受邀请后才能克隆私有仓库。当前还未发送协作者邀请。

## Codex 任务提示

请读取 AGENTS.md，在当前任务分支实现指定 XMind 用例。只改负责的模块，沿用现有登录、执行和报告机制。预期不清时记录待确认，不自行编造。运行相关检查并报告实际结果和未验证项。不要修改被测系统，也不要把凭证、数据库数据或登录态加入 Git。

公共改动在任务表记录负责人和影响。冲突时先查看 git status，让 Codex 对比双方意图；解决后重新验证，不强制推送或全量覆盖对方代码。
