# 运行报告管理

用户批准独立预览后实施。正式入口 `?page=run-reports`，归 Dify 工作区，侧栏沿用当前项目。

## 数据与管理

- 列表直接引用 SystemModuleRegression 的模块批次和 DepartmentCoreChainStore 的历史链路，不复制执行结果。核心报告按步骤计数，普通报告按当时所选用例计数。旧 starter/core 模块范围归自选，不冒充新的核心链路。
- 报告详情读取同一批次的结果、原版本、真实预期/实际及证据入口。异常和范围外独立统计，不归成失败或通过；未执行不补判通过。
- 核心历史按项目收集，保留过去账号和环境的记录，不因切换当前账号而隐藏。执行测试原来的账号/环境过滤保持原样。
- 名称、备注、重要标记独立保存于各工作区 `run-report-metadata/records.sqlite`，不会修改批次、用例、脚本、审批或业务数据库。保存带 revision，并发版本不符返回409，拒绝覆盖。
- 列表支持名称/编号/备注查询、范围/结果/时间筛选、仅重要、分页。报告信息持久化，选择与筛选是当前页面状态。

## 导出与边界

- 复用 system-module-report-export 的原有取数、安全校验、截图及 Excel/XMind 格式。仅抽出文件构建与下载函数；执行测试快捷下载继续使用同一导出实现。
- 多选下载打包 ZIP，每次最多10份，生成体积超过128MB提示分批；报告仍用原批次标识命名。批次正在运行时，管理页暂不导出。
- `/api/system-module-regression/reports?systemId=...` 为列表，`/reports/{batch|core}/{id}?systemId=...` 为详情，`POST /reports/{batch|core}/{id}/metadata` 为信息保存。
- 入口路由、导航和样式加载新增 run-reports 所有权。旧 history / run-detail 留在原网页工作区，通过“更多工具 → 其他工具运行记录”访问；不迁入或改写其他人的数据。
- UI、后端均使用项目范围校验；截图为同一历史步骤已经保存的证据，不抓取新页面充当历史证据。
