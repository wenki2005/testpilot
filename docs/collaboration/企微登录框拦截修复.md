# 企业微信登录框误拦截修复

问题：真实部门申样系统登录页中显示“此页面已被 Microsoft Edge 阻止”，无法显示二维码。

## 已确认原因

在系统专用测试窗口记录到企业微信 iframe 请求 `https://login.work.weixin.qq.com/wwlogin/sso/login` 失败，错误是 `net::ERR_BLOCKED_BY_CLIENT`。这是 TestPilot 的路由请求规则阻止，未观察到该请求到达后因 X-Frame-Options 被拒绝的证据。

原策略只允许在登录接力中已识别到的外部认证来源。首次二维码 iframe 在接力注册前发起，先被阻止，失败 frame 又无法登记来源，形成循环依赖。之后还发现 SDK 静态预取资源被浏览器分类为 other，以及嵌套登录存储页面受同样限制。

## 修改

- 给请求上下文增加当前是否处于认证页面的信息，Dify 连接预检和网页执行器共用该判断。
- 在认证页面或人工登录接力阶段，精确放行企业微信 SSO 来源及路径，以及 `open.work.weixin.qq.com/wwopen/loginStorage`。
- 对已观察到的企业微信 SDK CDN JS/CSS 预取补充静态资源类型规则。
- 在登录阶段允许同站点 API 的 `/supply-api/logWeChat/dept-book` GET/HEAD/OPTIONS 回调兑换，仍限制来源和路径。
- 业务提交、创建订单、审批修改等写请求继续被阻止；没有关闭浏览器安全选项、改写二维码或改动被测前端。

## 验证

- 修复前真实页面请求失败 `ERR_BLOCKED_BY_CLIENT`；修复后企业微信登录页面 HTTP 200，二维码图像实际加载，尺寸 585×585。
- 修复后登录 iframe 与嵌套登录存储 iframe 均已加载，没有 Edge 阻止页面。
- 无关统计请求和本机客户端自动登录探测仍可被阻止，不影响当前二维码显示；未扩大到任意第三方接口。
- 新增策略行为测试，验证首次 iframe、登录轮询、同站点兑换、静态预取、来源及业务写请求边界，以及导出的独立请求策略。
- 新增浏览器集成测试，验证首次二维码 frame、嵌套存储页、同站点回调请求与业务提交拦截。该测试使用受控页面验证规则，实际二维码加载另由真实站点验证。
- 71 项 Node 测试、8 项页面测试通过。首次浏览器集成测试因测试 HTML 未声明 UTF-8 而乱码，已修复测试响应编码，原断言保留；最终页面回归结果见 `.local/wecom-login-browser-final.log`。
- 已脱敏真实证据：`artifacts/wecom-login-verification/real-qr-final.json`，只记录来源/路径、图像加载与错误分类，不保存二维码内容、登录 code、Cookie 或 token。

## 仍需人工完成

用户使用所属企业的企业微信扫描真实测试窗口中的二维码并确认，再回到 TestPilot 点击“我已登录”。二维码可显示不等于账号已经认证或业务权限已经验证。
