# TestPilot 0.3.0 Windows 使用与维护说明

这是独立的本地测试应用。**不需要安装 Codex、登录 Codex 或购买 Codex 订阅。**

当前发布：2026-11-03 A01。包含网站自主探索、保存路径复用、用例自动选页，以及探索页面和异步请求关闭的修复。程序与网页界面均从当前源码重新构建。

## 安装与启动

1. 准备 Windows、Node.js 22.19.0 或更新版本，以及 Microsoft Edge。
2. 将发布 ZIP 完整解压到一个普通文件夹；不要在压缩包预览中直接运行。若发布方同时提供 `.sha256` 文件，可先用 `certutil -hashfile <ZIP路径> SHA256` 核对压缩包摘要。
3. 双击 `启动演示.cmd`。首次启动需要联网运行 `npm ci` 安装依赖；安装完成后会自动启动本机服务。
4. 等待终端显示地址，再用浏览器打开 `http://127.0.0.1:4317`。
5. 停止服务时，在启动终端按 `Ctrl+C`。如果端口 4317 已占用，在 PowerShell 中运行 `$env:PORT='4318'; .\启动演示.cmd`，然后打开 `http://127.0.0.1:4318`。

应用运行所需的源码搜索程序由项目依赖提供，无需额外安装 ripgrep 或 AI 编程工具。

## 本地示例

- **离线 API 示例**：在主工作台运行内置 API 示例，查看步骤、证据、报告和回归结果，无需模型密钥。
- **本地项目测试**：进入「工具 → 本地项目与脚本」，运行随包“数量校验样例”。样例故意把数量上限写为 999；测试发现 1000 或 9999 被截断时应显示失败。这是预置缺陷演示，不是真实业务结果。
- **代码测试 Agent**：进入「工具 → 代码测试 Agent」，选择“数量校验样例”，填写需求 ID、预期和调查目标，再选择生成模式。它可以读取源码、生成候选测试、实际运行测试并调查失败。真实模型功能需要使用者在「设置」中填写自己的兼容模型 API 地址、模型名和密钥。

可用于数量样例的任务描述：

> 根据 requirements.md 验证 QTY-001 和 QTY-002。生成独立的 Node 测试，使用 run_tests 实际执行，依据失败搜索源码并说明预期与实际。保留业务源码和既有测试，不跳过失败。

源码测试会执行候选代码；项目副本不等于操作系统沙箱。只对可信的隔离测试项目运行。

## 网页回归的首次接入

1. 在主导航进入「网页回归」，展开「首次接入 · 新建项目」。填写项目名称和目标网址，选择实际端类型，并导入需求或用例资料。
2. 创建后先核对项目端类型、入口、网站版本、模块路径、每条用例的预期、步骤、前置、账号角色和测试数据。端类型或用例有变化时，需要重新审核。
3. 将项目、用例、步骤、测试参数及副作用风险审核通过后，项目才可运行。缺少角色、数据、预期、可执行步骤或写入清理方案时应先补齐；不要为了启动而绕过阻断。
4. 如需使用模型生成或分析内容，在「设置」配置使用者自己的模型服务。固定常规回归不需要模型；登录由使用者在自己的浏览器会话中完成，TestPilot 不会代为获取账号或验证码。

首次接入完成后，日常操作从页面上方「日常运行」区域开始，无需再次导入同一资料。

## 认识网站与 A01 导航

1. 配置自己的模型服务，在「网页回归」选择项目并打开目标网站；需要登录时，在 TestPilot 的测试浏览器窗口完成登录。
2. 在「开始测试 → 认识这个网站」点击「探索网站」。Agent 会识别当前账号可见的安全菜单、列表和详情入口，保存页面和导航路径。
3. 展开「查看页面与路径」查看真实发现的页面，可点击「验证这条路径」从项目入口重新走到该页面。页面上分别显示探索结果和最近路径复验结果；服务重启后会重新显示待复验。
4. 后续用例准备会结合已发现页面的类型、内容和指定记录选页，再采集当前证据编写步骤。订单和申请页面分开匹配；没有记录的订单列表不会被当成订单详情。

这一步验证导航和选页；业务规则、角色、数据条件和断言结果仍在测试运行中分别验证。探索有页面、操作和时间预算；遇到缺数据、登录或不支持的入口会保留具体原因。A01 本轮验收说明位于 `docs/architecture/A01-网站自主探索与导航-2026-11-03.md`。

## 日常模块回归、结果复核与复测

1. 在「网页回归」选择已审核的项目，核对当前版本、目标网址、项目端类型和账号档案。
2. 在「日常运行」选择账号档案、测试数据组和回归模块。页面会展示直接目标和自动前置数量；系统按已审核的依赖顺序加入前置用例。
3. 检查启动阻碍。若页面显示缺少必需数据、账号、审核或可执行步骤，先处理阻碍再运行。需要暂停给 AI 查看前置后的页面时，选择「前置完成后暂停给 AI 观察」；确认页面证据和原文引用后，再手动继续。页面或运行上下文丢失时，系统会阻断，不应把它当成续跑成功。
4. 单条或模块运行结束后，先看总状态，再逐条查看目标用例和自动前置结果。展开用例可查看受限 BrowserStep DSL、来源和预期；失败记录可查看日志、截图、检查点及调查依据。可选的「截图像素分析」默认不发送图片；需要视觉观察时，必须针对具体截图点击分析并再次确认，截图图像字节会发送给当前配置的模型。分析结果只是待验证的视觉观察，不代表通过/失败，也不会修改用例或自动重跑。此处显示的 DSL 不是 JavaScript 源码或代码行导航。
5. `失败`、`阻碍`、`未验证`、`已取消`和`未运行`是不同状态；未运行或阻碍项不能算通过。修复后可重新审核并另起一轮复测，旧运行及其证据会保留。
6. 在当前结果区下载「本轮报告」和「可复用脚本包 ZIP」。进入主导航「运行记录」可打开历史轮次并核对版本、用例范围、数据版本与证据；历史结果不会因新一轮复测而覆盖。

**不要直接对生产系统执行。** 在真实业务上运行前，先确认隔离环境、专用角色和数据、复位/清理办法及写入补偿。此安装包没有预置任何业务账号、登录态、Cookie 或专用 fixture；本地示例也不能代替业务验收。

## 配置、数据与隐私

首次启动会创建 `runtime-data/`，保存本机模型设置、测试项目、用例、运行记录、证据和报告。配置模型后会使用该服务对应的 API 额度。除非在运行结果中对单张截图明确确认「发送所选截图并分析」，否则截图像素分析不会把图片发送给模型；历史分析读取的是本地已保存结果。

转发安装包时发送原始 ZIP。**不要把运行后生成的 `runtime-data`、`.env`、登录信息、截图或业务报告再次压缩分享。** 这些文件可能含密钥、业务数据或页面证据。安装包不含开发者模型密钥、数据库凭据、业务数据或浏览器配置目录。

## 更新与备份

1. 在启动终端按 `Ctrl+C` 停止旧版本；确认旧进程已退出。
2. 如果需要保留项目、记录和本机模型设置，将旧目录的 `runtime-data/` 复制到安全位置。备份按敏感业务数据管理，不要发给其他人。
3. 将新版 ZIP 解压到一个新目录，并按首次启动步骤打开一次，确认新版本能正常启动。
4. 停止新服务后，将备份的 `runtime-data/` 复制到新目录。不要把旧 `node_modules/`、`dist/` 或整个旧安装目录覆盖到新版。
5. 重新启动并检查项目、历史记录和报告能正常打开；确认无误后再归档或删除旧安装目录。

## 自检与故障处理

- 包内带有预编译的 `dist/` 和 `web/dist/`，正常启动无需重新构建。`MANIFEST.sha256` 是逐文件校验清单，`RELEASE.json` 记录版本和构建时间。
- 在解压目录运行 `npm run test:all -- --keep` 可执行该发布包的自检子集；浏览器自检使用 Edge，不包含开发仓库中的全部集成用例。
- 新增的 A01 浏览器自检也使用 Playwright Chromium；如本机尚未安装，先运行 `npx playwright install chromium`。正常使用已安装的 Edge 不要求执行这些自检。
- 提示找不到 Node.js：安装 Node.js 22.19.0 或更新版本，然后重新双击 `启动演示.cmd`。
- 首次启动依赖安装失败：确认网络可访问 npm registry，再重新启动；依赖尚未安装完成前服务不会启动。
- 页面无法打开：检查启动终端是否报告服务已启动，并确认访问的端口与终端显示一致；端口冲突时按启动步骤换一个端口。
- 网页回归无法启动：查看页面列出的审核、角色、数据或用例阻碍。没有登录态时，先在使用者管理的浏览器窗口完成人工登录；TestPilot 不保存或索要密码、验证码。
