# 从需求文档到可复用测试包：可行性与 MVP 方案

评估日期：2026-10-15  
依据：当前 TestPilot Demo、用户提供的部门申样书需求 PDF 与 XMind 测试用例，以及对测试站点的 10 项表单检查结果。

## 结论

**可行，且现有项目已有可复用的底座；但这是一项新功能，不是打开现有按钮就能完成的能力。** 当前 TestPilot 已有“候选脚本 → 人工审核/批准 → 无模型确定性重跑 → JSON/Markdown 报告”的生命周期，以及仅限 Grammar Lab 的自然语言测试候选生成。当前为部门申样书单独写的 Playwright 用例在 `D:\test agent\sample-apply-e2e`，没有接入 TestPilot 的文档导入、双引擎运行和打包流程。

部门申样书的 XMind 本身是 ZIP 容器，内含 `content.json`，可递归还原用例树。PDF 需求文档也可先抽取文本供 AI 起草用例，再由人复核。因此可以用已提供的实际材料做首个 MVP，不必先寻找另一套项目样例。

## 当前能力盘点

| 目标能力 | 现有能力 | 主要缺口 |
|---|---|---|
| 根据文档设计测试用例 | 已有 AI 从一段自然语言生成候选 DSL 的流程；有 PDF/XMind 档案与手工计划 | 没有 PDF/XMind 上传、解析、章节/需求追溯或大批用例生成；当前只支持 Grammar Lab |
| 生成可复用测试脚本 | 已有脚本快照、差异审核、审批版本和无模型 runner；Grammar Lab 有安全 DSL | 外部目标站点不能登记为通用 profile；部门申样书用例仍是独立脚本；没有从结构化用例自动编译本项目 Playwright 用例的通路 |
| AI 测试作为独立复核 | 有受限 Pi Agent API 探索演示 | 只覆盖内置 `/sample/*` API；不能浏览部门申样书；没有将 AI 发现与固定用例结果关联、去重和判冲突的流程 |
| 生成报告 | 已有 JSON/Markdown 报告、单次运行历史和产物留存 | 缺少逐用例 traceability、AI 发现与脚本断言的并列证据、差异摘要和覆盖/阻塞说明 |
| 可移交的测试包 | 已有可批准的脚本源快照 | 没有 ZIP 导出、独立运行说明/环境样例、脱敏规则或接收方可验证的校验值 |

## MVP 用户流程

1. **导入需求**：上传 PDF、XMind 或 Markdown。解析为章节/节点与原文片段；文档内容仅视为需求数据，不执行其中的命令或网页指示。
2. **生成测试用例草案**：AI 依需求源句生成结构化用例：ID、优先级、前置条件、步骤、输入、预期、风险等级、来源定位、是否允许自动执行。标记冲突/待澄清规则；AI 不自行把猜测转成通过标准。
3. **审阅和批准**：用户编辑/删改/批准用例。只有批准的用例可编译脚本。生产环境默认只允许只读和本地校验；提交、删除、审批、库存、支付、发信等副作用步骤必须指定隔离 QA 环境后才能启用。
4. **编译可复用脚本**：将批准用例编译为固定版本的 Playwright 测试项目，使用 locator/断言/截图等既有能力；不允许模型输出任意 JS 或 shell。脚本需在干净浏览器或用户手动登录的会话中启动，不把 Cookie、token、账号密码放进压缩包。
5. **双引擎验证**：同一目标运行两路：
   - **固定脚本**：确定性地执行已批准的需求用例，预期值来自人审后的测试用例。
   - **AI 自主探索**：在单独浏览器上下文和预算内观察页面、尝试未覆盖的非破坏性交互，并提交带截图/DOM证据的候选异常。
   - **互证**：报告列出两路各自结果、相同问题、仅脚本发现、仅 AI 发现与冲突项。AI 发现默认是“待复核”，不能篡改固定预期或单方面把测试改成通过。
6. **出报告与打包**：报告含需求到用例到断言的追溯、结果、证据、环境/浏览器/runner/模型版本、失败重现步骤、阻塞原因和未覆盖范围。ZIP 包含批准脚本、锁定依赖、运行入口、README、测试数据模板和脱敏后的报告/证据；不包含密钥、用户凭证或浏览器存储状态。

## 用当前样书系统演示的验收目标

- 导入《部门申样书需求文档 V1.0.pdf》和 `部门申样书_V1.0_测试用例.xmind`，保留来源引用，产出可审阅的用例清单。
- 从已批准的安全表单用例编译脚本，重跑当前已经确认的表单用例；将数量 9999 被截为 999、错误手机号失焦无提示列为失败/待澄清，不把它们解释为产品已修复。
- AI 独立检查未覆盖的低风险页面行为，不能点击提交申请或访问可导致真实数据变化的功能。
- 生成包含结果、截图、需求追溯和阻塞项的 HTML/Markdown/JSON 报告与 ZIP 包。
- 在没有模型服务时，批准脚本仍可独立复跑；AI 引擎缺失或失败时明确记为“未执行/阻塞”，不能记为通过。

## 建议分期

### MVP：文档到人工批准的回归套件

先支持 XMind 与 Markdown，接着支持 PDF 文本提取。实现源文档归档、结构化用例草案、手工编辑/批准、安全 DSL 编译、Playwright 确定性重跑、报告及 ZIP 导出。用样书申请表跑通“导入 XMind → 批准用例 → 执行 → 下载报告/测试包”。

### Demo：加入 AI 自主复核

浏览器适配器在独立会话内只做只读探索/表单本地验证；使用动作、时间、页面范围与副作用预算。AI 只能输出候选发现和证据，不得自动提交、批准或改写期望。让 AI 和固定脚本结果在报告中按需求 ID 互相对照。

### 成品：多应用、多运行环境和 CI

增加 API、浏览器、移动端和桌面端适配器；QA 环境/角色/测试数据配置；并行 worker；权限分层；脚本签名与版本存储；CI 入口；浏览器 trace、失败重试和数据清理机制；以真实项目验证误报率、覆盖率和复跑稳定性。

## 需满足的条件与风险

- **环境**：当前只有可访问的站点页面和表单级检查；全流程要有测试 URL、QA 账号/角色、可重置数据、API/业务配置和服务端日志。凭证应由用户在运行环境中安全配置，不通过聊天或报告传递。
- **规则完整性**：文档里有 24/72 小时等规则冲突以及待澄清项；正式生成脚本前需保留冲突并阻止自动编译成断言。
- **测试安全**：AI 自主探索不是自由代理。默认禁用提交、审批、库存/出库/物流写入、通知、支付、删除、文件上传和生产数据变更。
- **“双重验证”的边界**：AI 与固定脚本可以互相补盲，但两者可能受同一需求误解影响，不能替代人工评审、后端验证或独立测试数据。
- **测试包可移交**：只打包测试代码、锁文件、配置模板、说明和脱敏证据。对方须提供自己的测试环境与凭证，避免把生产会话 Cookie/令牌复制给他人。

## 建议的下一步实现切片

先在现有 TestPilot 建立 `document-test-project` 概念，支持 XMind JSON 的确定性解析与 Markdown/PDF 输入的抽取；用模型生成结构化候选用例；人工批准后把安全子集编译到 Playwright；并输出报告与 ZIP。第二步再将 Pi Agent 浏览器探索接到相同项目上，做独立复核。这样可以先交付无模型可复跑资产，再让 AI 增强覆盖，不会把系统可用性绑定到模型服务。
