# 部门申样书系统：需求驱动测试计划

来源：用户提供的《部门申样书需求文档 V1.0.pdf》（版本日期 2026-09-21）。

## 测试边界

目标系统包含员工侧企业微信小程序/H5、PC 管理端，以及企业微信审批、易诚通、旺店通和物流查询等接口。测试应覆盖表单、权限、审批、库存与发货状态、历史记录和管理查询。

先在隔离的 QA 环境执行无副作用检查。不要在生产环境提交申请、触发 OA 审批、锁定库存或创建发货单。后端链路验证应使用沙箱/Mock 数据和专用测试账号。

## P0：只读或客户端验证

| ID | 场景 | 操作/输入 | 预期 |
|---|---|---|---|
| AUTH-01 | 非公司员工访问 | 使用非企业成员身份进入员工端 | 阻止访问并显示无权限提示；不创建申请 |
| AUTH-02 | 企业成员授权登录 | 通过企业微信身份授权 | 获取姓名、公司和部门；仅显示当前账号允许的数据 |
| FORM-01 | 必填项为空 | 留空申请人、用途、图书明细、收货信息后触发前端校验 | 标记缺失项并阻止继续；不发起 OA 请求 |
| FORM-02 | 手机号边界 | 输入 10 位、12 位、含字母号码及 11 位有效格式 | 非法格式字段标红/提示；有效格式通过前端校验 |
| FORM-03 | 文本长度 | 收货人 20/21 字符、地址 20/21 字符、备注 30/31 字符 | 按文档上限接受边界值，超过上限时阻止或提示 |
| FORM-04 | 地区选择 | 分别选择省、市、区，并只选上级地区后尝试继续 | 级联选项有效；不完整地区信息不能通过必填校验 |
| BOOK-01 | ISBN/ERP 编码查书 | 输入有效图书编码 | 展示图书名、出版社、定价等接口数据，可加入明细 |
| BOOK-02 | 无效/未知编码 | 输入格式错误或不存在的编码 | 明确展示校验失败/未获取到图书信息；不能添加错误图书 |
| BOOK-03 | 重复图书 | 同一本书加入多个明细行 | 数量、单价、合计保持一致；按产品规则合并或分别列示 |
| CALC-01 | 费用计算 | 加入多种定价与数量的图书 | 每行小计=数量×定价；总计等于各行小计之和；数量变化立即重算 |
| WEIGHT-01 | 重量上限 | 测试合计 19kg 和略高于 19kg 的订单 | 19kg 边界按规则允许；超过 19kg 显示超重提示并阻止提交 |
| LOOKUP-01 | 客户模糊搜索 | 用客户关键字搜索并选择结果 | 返回匹配客户；选择后费用归属与客户编码正确关联 |
| UI-01 | 设备适配 | H5/小程序窄屏、PC 管理台常见分辨率 | 表单、确认信息、错误提示、列表列和弹窗可读、可操作，无关键内容溢出 |

## P1：隔离 QA 环境中的业务流程

| ID | 场景 | 验证要点 |
|---|---|---|
| FLOW-01 | 新建营销用书申请 | 申请人/代申请人、用途、图书、数量、费用归属、收货信息正确保存；返回可追踪申请编号 |
| FLOW-02 | 新建产品用书申请 | 与营销用书分流配置正确；用途、备注、审批人和订单字段符合相应规则 |
| FLOW-03 | OA 审批通过 | 审批状态/进度同步到员工端；通过后才进入库存检查与订单创建 |
| FLOW-04 | OA 审批拒绝 | 员工端显示拒绝状态和审批原因；不锁库存、不创建出库单 |
| STOCK-01 | 库存充足 | 锁定所需图书库存，成功创建对应出库/配送订单，并记录订单号 |
| STOCK-02 | 库存不足 | 不生成虚假成功状态；显示缺书原因，支持按文档流程联系运营或人工处理 |
| STOCK-03 | 锁库存失败/并发申请 | 返回可理解错误；不产生重复订单或超卖；失败申请可追踪 |
| SHIP-01 | 配送接口成功 | 返回运单号及初始状态，并在订单详情中显示 |
| SHIP-02 | 配送接口失败 | 显示失败原因或可恢复提示；保留申请及库存状态，不误报已发货 |
| TRACK-01 | 物流状态刷新 | 物流状态按配置周期更新，订单详情展示最近状态和轨迹 |
| TRACK-02 | 长时间无物流信息 | 触发提醒/异常状态/取消规则，并向员工或运营发送正确通知 |
| HISTORY-01 | 我的申请与订单列表 | 最新记录优先；支持状态、用途筛选、关键字搜索和每页 20 条分页 |
| HISTORY-02 | 详情一致性 | 从历史列表打开详情，申请编号、时间、申请人、图书、数量、收货信息、总价、订单及物流状态一致 |
| ADMIN-01 | 管理台访问控制 | 仅有权限的企业微信管理员可查看申请数据；普通账号不能打开管理功能或数据 |
| ADMIN-02 | 管理台筛选与分页 | 按申请时间、申请人、用途、审批/订单状态筛选；排序、分页结果准确 |
| ADMIN-03 | 管理台详情 | 申请详情、图书明细、审批流、物流详情字段完整且与员工端一致 |
| MSG-01 | 企业微信消息 | 提交审批、库存不足、长时间未发货等事件向正确对象发送正确模板和申请编号 |

## 必须先澄清的规则

1. **超时取消阈值冲突：** 文档前部写“24 小时未发货/无物流信息取消”，后部订单与消息规则多处写“72 小时”。确认统一时长、计时起点、触发条件及是否自动取消。
2. **19kg 适用范围：** 确认这是单个申请总重、每个包裹重量，还是按图书明细分别计算；确认恰好 19kg 是否允许。
3. **本期和后续范围：** 文档标注 WMS 仓库接口、出版社用书等部分为二期/暂不实现；部署环境应有功能开关或明确“不支持”，不应把计划功能误判为本期缺陷。
4. **审批规则：** 确认营销用书、产品用书是否都只需直属上级审批，是否存在金额/部门等条件分支。
5. **重试和幂等：** 确认 OA/库存/配送接口超时后重试策略、重复回调处理、库存解锁时机和订单去重键。

## 执行前置条件

- 需要员工测试账号、管理员测试账号和审批人账号；账号应属于 QA 企业/测试组织。
- 需要 QA 环境的企业微信、图书查询、客户查询、OA、库存、配送和物流接口，或可控 Mock 服务。
- 提交与审批用例会改变状态，应使用可重置的专用测试数据；不得连接生产库存、真实运单或真实通知群。
- 保存每次运行的应用版本、账号角色、请求/响应摘要、截图/日志、申请编号和清理结果；敏感令牌须脱敏。
