# 项目名称

**找代码先看：[代码导航](代码导航.md)。** 支持按中文功能、函数名、新旧文件名、用例编号定位。

## 部门申样自动化测试项目（TestPilot）

用于验证部门申样系统的申请提交、审批结果回传、库存与锁单、订单及物流等业务流程。主要通过网页运行测试，并管理用例、脚本和运行报告，支持按模块或核心链路组织测试。

## 先看这几个目录

| 目录 | 内容 |
| --- | --- |
| src | 服务端代码 |
| web | 网页代码 |
| project-resources | 当前用例、脚本和核心链路快照 |
| scripts | 启动、构建与维护工具 |
| tests | 工具自身测试 |
| docs | 当前说明、规范与后续实施计划 |

启动用根目录 **启动测试工作台.cmd**，关闭用 **停止测试工作台.cmd**。程序与本机数据分开保存，默认数据位置为 `%LOCALAPPDATA%/TestPilot/workspaces/dify`。

当前主要页面：

- **执行测试**：选择执行范围、模块或核心链路，查看对应批次的结果及证据。
- **用例与脚本**：查看全部用例或核心用例、前置用例及对应脚本，编辑、保存并查看修改对比与版本。
- **运行报告**：查阅历史结果和截图，筛选报告、管理名称备注和重要标记，按需下载。

项目持续更新中，部分功能尚未完成。使用说明以当前发布版本的网页功能为准，随版本同步维护。

## 运行条件

- Windows、Microsoft Edge，Node.js 22.19 或更高版本。
- 源码版首次安装依赖需要 npm 及相应网络访问；完整Windows包已带Node.js和依赖。
- 能访问被测系统，准备自己的测试账号；所选用例需要的数据库、审批、库存及下游服务条件另行配置。
- 首次启动自动加载内置资源，在自己的数据区建立项目。完整包解压后双击启动，详见[运行包说明](packaging/windows/README.md)。

## 运行说明

### 当前开发环境

在仓库根目录安装依赖并构建：

```powershell
npm ci
npm run build
npm run workbench:start
```

服务启动后打开 [测试工作台](http://127.0.0.1:4325/dify/?page=dify-regression)。启动入口复用已有实例，不要求为每次打开网页重新启动服务；端口被其他服务占用时会报错。

依次选择项目，在“用例与脚本”查看内容，在“执行测试”选择范围运行，再到“运行报告”查阅记录。根目录统一使用“启动测试工作台.cmd”。

### 文件在哪里

| 内容 | 目录 |
| --- | --- |
| 系统服务端源码 | `src/`；服务入口 `src/server/http-server.ts`，执行和业务场景在 `src/adapters/regression/` |
| 页面源码 | `web/src/app/` 管理工作台；`web/src/features/` 按执行测试、用例脚本、报告等功能分类 |
| 启动、构建、导出、打包 | `scripts/`，按用途分类；不保存历史转发副本 |
| 当前业务定义快照 | `project-resources/department-sample/` |
| 原始用例来源及前置编号 | `regression/packs/`、`regression/plans/`，原始文件用于追溯预期 |
| 本机运行数据、截图与私有配置 | `%LOCALAPPDATA%/TestPilot/workspaces/dify`，不提交 Git；旧数据迁移保留回退副本 |
| 详细规范 | [目录规范](docs/project-layout.md)、[命名规范](docs/naming-conventions.md) |

## 测试说明

- 用例及链路持续维护，以当前网页加载的版本为准。前置用例需要执行通过，脚本存在不等于通过。
- 结果按实际证据区分通过、失败、阻塞和未执行，历史报告保留对应版本与结果。
- 本次整理的资源快照包括 131 条定义、5 个模块、4 条核心链路；131 份对应脚本中 74 条含步骤、57 条尚无步骤。未完成项保留，不视为全部实现或通过。
- 提交、撤销、审批和下单需使用约定测试数据及已授权环境；结果未知时先查询，避免同一操作意外重放。
- 工具自身测试位于 `tests/`，与部门申样业务回归分开。目录整理没有触发业务测试或目标数据库写入。

## 技术架构

Node.js / TypeScript 服务端，React / Vite 网页端，Playwright 浏览器执行；本机存储包含 SQLite，业务数据库连接按环境配置。

源码、业务资源、发行产物、本机数据分别管理。源码不重复维护多份；发行包应包含程序、全部用例和已有脚本，不包含使用者的历史记录、截图、密钥或登录态。

业务资源按用例ID逐条保存。当前以网页有效版本及缓存执行；可在“用例与脚本 → 资源”导出和预览导入，或用npm run resources:sync同步文件目录。直接修改文件不会静默覆盖网页，详见[资源同步](docs/tooling/project-resources.md)。

首次启动应有131条定义和已有脚本，全部未执行，报告为空。重复启动保留本机编辑，详见[首次启动](docs/tooling/first-run.md)。

源码版也使用外部数据目录。迁移和升级规则见[本机数据](docs/tooling/local-data.md)。后续MCP等功能进度见[模块交付计划](docs/planning/delivery-plan.md)。

源码提交和发行包的内容边界见 [上传与分发](docs/publishing.md)。
