# TestPilot 0.3.0 Windows 使用说明

继续 Dify 开发或换电脑，请先读 [Dify 新电脑交接](docs/collaboration/Dify新电脑交接-2026-11-01.md)；代码、工作台本机配置与登录态的迁移方式不同。

> 两种用法，别混：
> - **发行 ZIP**：包内带预编译的 `dist/`，按下面“启动”双击 `启动演示.cmd`，默认 4317。
> - **从 GitHub 源码克隆**：`dist/` 不在 Git 里，先 `npm ci`、`npm run build`，再按 [Dify 新电脑交接](docs/collaboration/Dify新电脑交接-2026-11-01.md) 导入配置；Dify 回归用 `scripts/start-dify.ps1`（默认 4319，需先按交接第 3 节创建 `.env`），不要用本文件下面的 4317 演示流程。

这是独立的本地测试应用。**不需要安装 Codex、登录 Codex 或购买 Codex 订阅。**

## 启动（发行 ZIP）

1. 准备 Windows、Node.js 22.19.0 或更新版本，以及 Microsoft Edge。
2. 完整解压 ZIP，建议放在自己的普通文件夹里；不要在压缩包内直接运行。
3. 双击 `启动演示.cmd`。首次启动会联网执行 `npm ci` 安装依赖；后续复用已安装的依赖。
4. 等待终端显示服务地址，然后用浏览器打开 `http://127.0.0.1:4317`。
5. 停止时在启动终端按 Ctrl+C。端口占用时，在 PowerShell 设置 `$env:PORT='4318'` 后运行 `./start-demo.ps1`。

应用运行所需的源码搜索程序由项目依赖提供，无需额外安装 ripgrep 或任何 AI 编程工具。

## 使用哪些功能

- **离线样例**：在主工作台运行内置 API 示例，查看证据、报告和回归结果，无需模型密钥。
- **代码测试 Agent**：「工具 → 代码测试 Agent」，选择“数量校验样例”，填写需求 ID、预期和调查目标，选择生成模式。它可读取源码、编写并实际执行测试、调查失败，并提交候选。真实模型功能需要在“设置”中填写使用者自己的兼容模型 API 地址、模型名和密钥。
- **固定回归**：「工具 → 本地项目测试」可运行随包数量样例。该样例故意把数量上限写为 999，测试发现 1000/9999 被截断时应显示失败，这是演示的预置缺陷。
- **网页回归**：可导入自己的需求、用例，设置目标与测试数据，通过现有审核流程运行并导出报告。真实业务的账号、角色、接口和数据由使用者提供；包中没有任何人的登录状态。
- **继续任务**：源码任务未完成时可以填写补充说明，继续使用保存的副本；候选修订会保留前后内容与依据。

可用于数量样例的目标：

> 根据 requirements.md 验证 QTY-001 和 QTY-002。生成独立的 Node 测试，使用 run_tests 实际执行，依据失败搜索源码并说明预期与实际。保留业务源码和既有测试，不跳过失败。

仅供可信、隔离的测试环境使用。源码测试会执行候选代码；项目副本不等于操作系统沙箱。

## 配置与数据

首次启动会创建 `runtime-data/`，保存本机模型设置、测试文档、运行记录和报告。模型配置由使用者自己提供，配置后使用相应 API 的额度。

转发时发送原始 ZIP。**不要把运行后生成的 `runtime-data`、`.env`、登录信息或自己的测试报告再次压缩发给别人。** 此包未包含开发者的模型密钥、数据库凭据、业务数据、Cookie 或浏览器配置目录。

## 自检与升级

发行 ZIP 包内带有预编译的 `dist/` 和 `web/dist/`，正常启动无需重新构建；从 GitHub 源码克隆则没有 `dist/`，必须先 `npm run build`。`MANIFEST.sha256` 是逐文件校验清单，`RELEASE.json` 记录版本与构建时间。

随包自检是可移植子集，可在目录中执行 `npm run test:all`；不包含开发机上其他项目的集成测试。浏览器自检使用 Edge。

升级时先停止旧服务，解压到新目录。需要保留自己的记录时，备份旧目录中的 `runtime-data`，再复制到新目录；它可能含私密配置，不应随分享包一起发送。
